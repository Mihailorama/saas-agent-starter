# 0003. Authentication and authorization

Status: accepted. Changed by ADR 0029: email one-time codes instead of email/password.

## Context

B2B SaaS needs email/password, organizations with roles, sessions, and SSO for enterprise
customers, without running and paying for another service on day one.

## Decision

- Sign-in by email one-time code (Better Auth's `emailOTP` plugin; the first sign-in creates
  the account), passkeys or SSO; no passwords (ADR 0029).
- Better Auth (MIT) as a library inside the API, storing users, sessions, organizations,
  members and invitations in our Postgres via the Drizzle adapter.
- Roles owner > admin > member from the organization plugin; `requireRole(min)` guards routes.
- Sessions in HttpOnly SameSite=Lax cookies; web and API share an origin (`/api` proxy).
- SSO: OIDC through Better Auth's generic OAuth plugin, enabled by env; SAML/per-org IdPs via
  `@better-auth/sso` when needed.
- Second factor and passkeys: Better Auth's `twoFactor` (TOTP, backup codes) and
  `@better-auth/passkey` (WebAuthn) plugins, with an org "require 2FA" policy (ADR 0017).

## Alternatives

- Keycloak (Apache-2.0): full IdP with admin console and federation. Choose it when customers
  require a standalone IdP; connect it to this app over OIDC. Not the default because it is a
  separate JVM service to run, upgrade and secure.
- Hosted auth (Auth0, Clerk...): vendor lock-in and per-user pricing.
